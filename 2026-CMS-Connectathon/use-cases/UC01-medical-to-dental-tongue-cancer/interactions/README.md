# UC01 Interaction-Level Materials

Clinician-readable writeups of UC01's key test interactions (not a 1:1 map to the 7 clinical encounters enumerated in the main use case document's Appendix Section 0 — that enumeration remains the clinical reference; test data is organized around integration-worthy interactions instead, since most of the clinical narrative, e.g. the tooth extractions, is "business as usual" and isn't separately modeled). See `CLAUDE.md` for the full reasoning.

- `interaction-01-request-for-radiation-referral.md` — built (corresponds to clinical Encounter #1)
- `interaction-02-request-for-additional-information.md` — built (corresponds to clinical Encounter #2 + the later treatment-extension moment, ~early August — both are instances of the same informal note-based inter-provider request pattern, per the base COW IG's "Requesting additional information" mechanism; the extension request was originally scoped as a separate "Interaction 3" but folded into Interaction 2 since it uses the identical mechanism)
- `interaction-03-the-clearance.md` — built (corresponds to clinical Encounter #6, the dental clearance visit). Business-terms writeup only so far — FHIR resources not yet built. Scoped in detail before writing: core deliverable is `ClinicalImpression`; two distinct Task transitions close here (the 360X referral Task, already built, transitioning to completed; a CDex documentation Task, not yet built at all — a retroactive gap in Interaction 1, which should have opened this Task at DTR launch); transmission mechanism (bare ClinicalImpression vs. wrapped DocumentReference vs. purpose-built ODE resource) is an explicitly open design question in the source use case doc itself, not yet decided.
- `interaction-04-ending-prior-authorization.md` — built (PA submission/approval, 2026-08-01–08-03). Claim is for the IMRT/radiation service, not Bellweather's dental work — dental clearance is supporting evidence, not the subject of the request.
